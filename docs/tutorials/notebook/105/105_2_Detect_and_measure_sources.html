2. Source detection, deblending, and measurement¶

Learn how to perform source detection, deblending, and measurement on a deep_coadd.

A deep_coadd is built by stacking visit images that have been warped onto a common pixel grid. Several of its properties matter for detection, deblending, and measurement:

  • dataId and geometry: Coadds are divided into tracts and patches of a skymap, so the dataId has tract, patch, band, and skymap. The pixel coordinates are those of the whole tract, so a patch's bounding box typically does not start at (0, 0).
  • Depth: The coadd is much deeper than any single visit, so many faint sources are detected, and blending of neighboring sources is common.
  • Background: The input images were background-subtracted before coaddition, so only a minimal (or no) re-estimation of the background is necessary.
  • Noise: Warping correlates the noise between neighboring pixels, and the depth varies across the patch depending on how many visits contributed to each location.
  • PSF: DP2 coadds are cell-based: each patch is divided into cells, and each cell has its own PSF model built from the visits that contributed to it. These are combined into a single PSF object (a CellPointSpreadFunction in lsst.images), so the PSF can change slightly from one cell to the next.

Note: The production Rubin pipeline processes coadds with dedicated tasks (DetectCoaddSourcesTask, the multi-band Scarlet deblender, MeasureMergedCoaddSourcesTask, and forced photometry) to create the Object table. The single-band processing here is a simplified analog meant to show the basic building blocks; the results will not match the Object table exactly.

The LSST Science Pipelines' source detection, deblending, and measurement tasks were imported in the first code cell.

2.3. Configure the tasks¶

Each task possesses an associated configuration class. The properties of these configuration classes can be determined from the classes themselves.

Option: uncomment the following line to view the help documentation for the SourceDetectionTask configuration. Replace SourceDetectionTask with another task name to view its help documentation.

In [13]:
# help(SourceDetectionTask.ConfigClass())

Set the basic configuration parameters and instantiate each task in turn.

SourceDetectionTask detects sources.

Set the configuration for the detection threshold to 4 (the default for LSST coadds is 5) in order to detect sub-threshold (faint) sources. Some of the faint detections will be spurious due to pixel noise.

Set the detection threshold type to be pixel_stdev, which means the threshold is applied to each pixel's own standard deviation, taken from the coadd's variance plane. This tracks the varying depth across the patch better than the stdev option, which applies the threshold to a single standard deviation for the whole image. In other words, this configuration using pixel_stdev will detect sources at $4\sigma$ relative to the local noise.

Two further settings, similar to those used for coadds in the production pipeline, are also applied:

  • reEstimateBackground = False: the background was already subtracted from the input visits.
  • isotropicGrow = True: grow footprints isotropically, which gives better footprint shapes for extended sources.
In [14]:
config = SourceDetectionTask.ConfigClass()
config.thresholdValue = 4
config.thresholdType = "pixel_stdev"
config.reEstimateBackground = False
config.isotropicGrow = True
sourceDetectionTask = SourceDetectionTask(schema=schema, config=config)
del config

SourceDeblendTask deblends overlapping sources into "parent" and "child" sources. The parent record represents the whole blend, and the children are the deblender's estimates of the individual objects within it.

No configuration changes are needed for this tutorial. When no config argument is passed, a task uses its default configuration, so there is no need to create a configuration object explicitly unless some of its defaults are to be changed.

In [15]:
sourceDeblendTask = SourceDeblendTask(schema=schema)

SingleFrameMeasurementTask measures the properties of the deblended sources.

No special configuration is needed for this tutorial. Note that SingleFrameMeasurementTask is indeed the correct task to run on a coadded image, in that the single coadd image is being analyzed on its own rather than in a forced photometry or multi-image manner.

In [16]:
sourceMeasurementTask = SingleFrameMeasurementTask(schema=schema,
                                                   algMetadata=algMetadata)

2.4. Source detection¶

The detection, deblending, and measurement tasks require their input image as an ExposureF. Use the to_legacy method of the CellCoadd to create an ExposureF version of the deep_coadd, which carries the coadd's PSF (as a StitchedPsf, the legacy counterpart of the CellPointSpreadFunction), WCS, and photometric calibration.

The tasks modify their input image: detection sets the DETECTED mask plane, and measurement temporarily replaces neighboring sources with noise while measuring each source. Setting copy=True makes the ExposureF an independent copy of the pixel data, so that the original deep_coadd, which is used for display in Section 2.6, is not affected.

In [22]:
legacy_coadd = deep_coadd.to_legacy(copy=True)
print(type(legacy_coadd))

<class 'lsst.afw.image._exposure.ExposureF'>

Clear the DETECTED information from the mask of the ExposureF, as source detection is re-done below.

In [23]:
legacy_coadd.mask.removeAndClearMaskPlane('DETECTED')

Run source detection by calling the run method of the SourceDetectionTask, which takes in-memory objects (here, the SourceTable and the ExposureF version of the coadd) and returns its results directly. The deblending and measurement tasks are run the same way in Section 2.5.

Calling run directly is convenient for running a single task interactively in a notebook, but it is not how tasks are run in production. There, tasks are combined into pipelines and executed by the pipeline framework, which reads each task’s inputs from the Butler and writes its outputs back to it.

In [24]:
result = sourceDetectionTask.run(tab, legacy_coadd)

With thresholdValue set to 4, roughly 4,400 sources are detected, containing roughly 8,000 positive peaks. Each source is a footprint: a connected region of pixels above the threshold. A footprint can contain more than one peak, and those that do are candidates for deblending in Section 2.5.

The measurement step logs a few WARNING messages from the base_PsfFlux plugin about an invalid pixel value. These are expected: they occur when pixels without valid data (for example, near the patch edges or in masked areas) fall under the PSF model of a source. When a measurement plugin fails, the measurement framework catches the error, sets a flag for that source (here, base_PsfFlux_flag), and continues; the source's other measurements, and all other sources, are unaffected.

2.6. Visualize sources on an image cutout¶

Overplot the detected sources on a cutout image of the deep_coadd using afwDisplay.

Use the bbox_from_sky_circle method of the CellCoadd to compute the bounding box of a circle on the sky, centered on the ECDFS coordinates from Section 1.2, with a radius of 30 arcseconds (150 pixels). This gives a cutout about 300 pixels wide and 300 pixels high. Setting clip=True clips the bounding box to the patch, in case the circle extends past the patch edge. The bounding box is in the tract's pixel coordinates.

In [34]:
center = SkyCoord(ra=ra, dec=dec, unit='deg')
bbox = deep_coadd.bbox_from_sky_circle(center, Angle(30, u.arcsec), clip=True)
print(bbox)

[y=4420:4721, x=14175:14476]

Option: Display the bbox information.

In [35]:
# bbox

Generate the cutout. Indexing an lsst.images image with a bounding box (e.g., deep_coadd.image[bbox]) interprets the box in the image's own pixel coordinates, here those of the tract, and returns a new Image covering that region.

In [36]:
cutout = deep_coadd.image[bbox]

Get the centroid pixel coordinates of all sources from the sources catalog, and use the contains method of the bounding box to select those that lie within the cutout. The source positions are in the tract's pixel coordinates, the same as bbox, so they can be compared directly.

Then select isolated sources, deblended children, and blend parents.

In [37]:
xs = sources['slot_Centroid_x']
ys = sources['slot_Centroid_y']
in_cutout = bbox.contains(x=xs, y=ys)

isolated = in_cutout & (sources['parent'] == 0) & (sources['deblend_nChild'] == 0)
child = in_cutout & (sources['parent'] != 0)
blend = in_cutout & (sources['deblend_nChild'] > 0)

Display the cutout with afwDisplay. afwDisplay accepts lsst.images objects directly, and uses the image's sky projection as its WCS, so the axes are labeled in RA and Dec. Mark isolated sources with orange circles, deblended children with cyan circles, and blend parents with magenta plus marks, at their pixel positions from the sources catalog.

In [38]:
fig = plt.figure(figsize=(7, 7))
display = afwDisplay.Display(frame=fig)
display.scale('asinh', 'zscale')
display.mtv(cutout)
for x, y in zip(xs[isolated], ys[isolated]):
    display.dot('o', x, y, size=8, ctype='orange')
for x, y in zip(xs[child], ys[child]):
    display.dot('o', x, y, size=8, ctype='cyan')
for x, y in zip(xs[blend], ys[blend]):
